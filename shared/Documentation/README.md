# Documentation

**Holds:** the client's documents about their world: system and integration docs, data dictionaries, API specs, process descriptions, onboarding guides, access instructions (never the credentials themselves).

**Naming:** keep the client's own file names, so both sides can find them. Group them by source system in subfolders (`<System>/`) once there are more than a handful.

**Written by:** the client and the team. **Read by:** people and agents researching the client's systems. Facts from here that a decision rests on are cited in Git, and anything not yet confirmed gets a `q…` or `a…` id in `architecture/questions.md`.

**Rules:** documents that contain personal or customer data stay in the client's systems; keep a pointer here instead.
