# Team

**Holds:** who is on the team and what everyone can expect from everyone, plus the live, human side of governance: directives, raw ideas, and proposals waiting for a decision. This is the one place where people's **names** belong. Files in Git name roles, and this folder maps roles to people.

| Path | What | Read by the digest |
|---|---|---|
| [`Team structure.md`](Team%20structure.md) | Roles, people, allocation, time zone, how to reach them | yes: who is who |
| [`Responsibilities matrix.md`](Responsibilities%20matrix.md) | What each role owns and decides, what it expects from the others, and a RACI per activity | yes |
| [`Competency matrix.md`](Competency%20matrix.md) | Skills by person, to plan pairing, cover and hiring | no |
| [`Directives.md`](Directives.md) | Dated directives from the leads (priorities, constraints, milestones) | **yes, by date** |
| [`Bot notes.md`](Bot%20notes.md) | What the daily digest should know before it writes: context, tone, things to watch | **yes, always** |
| [`Ideas/`](Ideas/README.md) | Each person's raw ideas, dated, unfiltered | yes: new entries |
| [`Proposals/`](Proposals/README.md) | Pros-and-cons proposals asking for a decision; approved ones are promoted to Git | yes: open ones |

**Written by:** people. **Read by:** the team, agents, the daily digest.

**How ideas harden:** idea (`Ideas/`) → proposal with pros and cons (`Proposals/`) → decision → promoted to Git: an ADR backlog entry, a PRD change, a plan or a ticket. Only then does it bind anyone.
