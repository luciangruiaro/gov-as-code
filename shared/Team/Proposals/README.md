# Team / Proposals

When someone wants a decision, they write a **pros-and-cons proposal** here, and the team sees it straight away. Start from [`_template - pros and cons.md`](_template%20-%20pros%20and%20cons.md), and name it `YYYY-MM-DD - <question in a few words>.md`.

**Lifecycle:** `open` → `approved` | `rejected` → `promoted`. An approved proposal is **promoted to Git**, and the proposal links to where it landed:
- a technical decision → an ADR backlog entry (`architecture/decisions/backlog.md`), then an ADR;
- a product decision → a change to the master PRD (`PRD/`), then a sync;
- work → a ticket, or a plan (`resources/work/plans/`).

The daily digest lists open proposals and the ones decided since its last edition.
