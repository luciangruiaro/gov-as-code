# WORKSPACE.md: the map of Project Name's workspace

> Where everything lives, who writes it, and how it flows. It describes the current state only. Hierarchies here stay shallow (three levels at most); anything deeper is prose. The tree in section 2 is generated by `py -3.12 tools/workspace/index.py`; people keep the rest, and the `gov-workspace-map` skill proposes updates. **Refreshed:** 2026-01-15.

## 1. The workspace in one paragraph
The workspace has two halves. The **shared drive** (`shared/`) syncs in near real time across the team. It holds live material: the client's Word PRD, decks, call transcripts, team files, and one-way mirrors of the backlog and of in-app feedback. The **governance repository** (`git/project-gov/`, this repo) is versioned. It holds what is agreed and needs history: the PRD mirror, the architectural decisions, the deviation register, the open questions, the skills, plans, brainstorms and audits. The **product repositories** are cloned beside it in `git/`, so agents and the daily digest can read the code itself. Tickets and documents are claims; mainline code is the witness.

## 3. Git, shared drive or local only?
| | Git (this repository) | Shared drive | Local only (gitignored) |
|---|---|---|---|
| **For** | Agreed material that needs history and review | Live material that must reach everyone now | Personal settings and secrets |
| **Examples** | PRD mirror, ADRs, deviation register, questions, skills, plans, brainstorms, debug notes, audits, tools | Word PRD, decks, demos, transcripts, team files, backlog and feedback mirrors | `.env`, `.claude/`, `local-*` skills, `*.local.md`, `resources/local/` |
| **Changes by** | A reviewed commit | Saving a file | You |
| **History** | Full: `git log`, `git diff` | The drive's version history | None |
| **Names** | Roles only | Names allowed (in `Team/`) | Anything |

## 5. The shared drive
**Link it in** beside `git/`, once per machine, so every tool finds it through `workspace.toml` (`[shared] path`, default `../../shared`):
- Windows (a junction, no admin rights needed): `mklink /J "<workspace>\shared" "G:\Shared drives\<drive>\<folder>"`
- macOS or Linux: `ln -s "<path to the synced folder>" "<workspace>/shared"`

| Folder | Holds | Written by | Read by |
|---|---|---|---|
| `Assets/` | Brand guidelines, logos, screenshots | People | Decks, reports, UI work |
| `Decks/` | Presentations | People | Team, client, digest |
| `Delivery/` | Planner, risks and issues, weekly reports (`Updates/`) | Delivery lead, report tool | Team, client, digest |
| `Demos/` | Recordings and their scripts | People, film tool | Client, team |
| `Documentation/` | The client's own documents | Client, team | Research, decisions |
| `Feedback/` | One-way mirror of in-app feedback | `tools/mirrors/feedback.py` | Team, digest, triage |
| `Jira/` | One-way mirror of the backlog, by state | `tools/mirrors/backlog.py` | Team, agents, digest |
| `PRD/` | The master PRD in Word | Client, product people | `prd/sync/sync.py` |
| `Team/` | Structure, matrices, directives, ideas, proposals, bot notes | People | Team, digest |
| `Transcripts/` | Call notes and transcripts | Meeting tools, people | Team, digest |

`shared/INDEX.md` lists every file on the drive (generated). Google files (`.gdoc`, `.gsheet`, `.gslides`) are pointers with no content on disk: download them, or read them in the browser.

## 6. How information flows
```
 client & team ──edit──▶ PRD/*.docx ──sync.py──▶ prd/*.md ──git diff──▶ impact.py ──▶ audits/*_prd-adr-alignment.md ──gov-adr──▶ ADRs
 Jira / Azure DevOps ──mirrors/backlog.py──▶ Jira/         app database ──mirrors/feedback.py──▶ Feedback/
 product repos ──repos/sync.py──▶ git/<repo>/              ideas ──▶ proposals ──▶ ADR backlog ──▶ ADRs
                         all of it ──reporting/digest.py──▶ evidence bundle ──gov-digest──▶ team chat (approval-gated)
```

| Flow | From → to | Tool (skill) | Direction | When |
|---|---|---|---|---|
| Requirements | `PRD/` → `prd/` → audits worksheet → ADRs | `prd/sync/sync.py`, `impact.py` (`gov-prd-sync`, `gov-adr`) | One-way into Git | On each PRD change |
| Backlog | Jira or Azure DevOps → `Jira/` | `tools/mirrors/backlog.py` (`gov-backlog-sync`) | One-way out | Three times a day |
| Feedback | The app's database → `Feedback/` | `tools/mirrors/feedback.py` (`gov-feedback-sync`) | One-way out | Hourly in working hours |
| Code | Product repositories → `git/<repo>/` | `tools/repos/sync.py` (`gov-code-sync`) | Fast-forward only | Daily, before the digest |
| Ideas to decisions | `Team/Ideas/` → `Team/Proposals/` → `architecture/decisions/backlog.md` → ADR | `dev-brainstorm`, `gov-adr` | Into Git once decided | On decision |
| Daily digest | All of the above → team chat | `tools/reporting/digest.py` (`gov-digest`) | Out, approval-gated | Weekdays before stand-up |

Status: the PRD flow and the indexes are implemented. The backlog, feedback, code and digest tools are **stubs with full contracts**: implement each per project (`tools/README.md`).

## 8. Off-system sources
These matter but are not mirrored here. Nobody should assume they are covered:
- the client's internal tools and portals (name them here as they appear);
- email and private chats (decisions made there are restated in `Team/Directives.md` or a proposal);
- the contract (SOW) system: cite sections, never copy text;
- recordings kept in the meeting tool (`Transcripts/` holds the notes).

## 9. Schedules and notifications
The jobs, their times and the chat spaces they post to are in [`operations/README.md`](operations/README.md). The digest never posts without an approved draft unless its switch in `.env` is on.

## 10. Keeping this map current
- Update it when a repository, a drive folder or a flow is added or changes. A map that is wrong is worse than none.
- The tree is generated: run `py -3.12 tools/workspace/index.py` (`--check` in CI). The prose is kept by people; the `gov-workspace-map` skill compares it with the disk and proposes edits.
- Change the **Refreshed** date at the top with every edit.
