# prd/: the product requirements, versioned

| Path | What it is |
|---|---|
| `Product Requirements Document (Master) - <Product> vN.N.md` | The **mirror** of the master PRD, which lives in Word on the shared drive (`PRD/`). Generated by `sync/sync.py`. Never edit it by hand. |
| `assets/master/` | The mirror's images, extracted from the Word file. |
| [`sync/SYNC.md`](sync/SYNC.md) | The procedure: convert, read the diff, check, find the decisions it touches, log, commit. |
| [`sync/sync.py`](sync/sync.py) | Word → Markdown (pandoc 3+), keeping the change log at the end of the mirror. |
| [`sync/impact.py`](sync/impact.py) | Git diff of the mirror → the requirement ids that changed → the ADRs, questions and plans that cite them → an alignment worksheet. |
| [`templates/`](templates/) | The master PRD template (in the skeleton, also the sample PRD it demonstrates with). |

**Why a mirror?** The client works in Word, where they comment and agree. The team and the agents work in Git, where every version is kept, every change is a reviewable diff, and a changed requirement can be traced to every decision that rests on it. The mirror links the two worlds. It is one-way, so the two copies never compete.

**Requirement ids** are the contract between the PRD and the decisions. Keep them stable, one table row per requirement, and cite them from ADRs (`FR-001`), the ADR backlog, the open questions and plans.
